## Anti-Patterns Verdict

**Deterministic scan**: 8 findings, all `advisory`, all in `src/app/api/notifications/email/route.ts` (undocumented `#1a1a18`, `#a8a8a0`, `border-radius: 10px`). These are **false positives** for UI purposes — that file is an HTML email template, and email clients can't read the design system, so inline literals are required. ## Overall Impression

The craft here is real. The problem is not how it looks — it's that the design system was executed thoroughly on the *happy path* and thinly everywhere else. The single biggest opportunity: **the app's stated primary user — a floor operator on a phone — is the worst-served user in it.**

## What's Working

1. **The vocabulary layer.** `statusColors.ts`, `stages.ts`, `departments.ts` give one truth for stage naming and color across admin, track, and displays. This is why the app feels coherent, and it's the thing most projects skip.
2. **The prerequisite override flow.** Blocking an out-of-order stage move, then allowing Admin through with a *required written justification*, is thoughtful production-floor design.
3. **Theme discipline.** The `.admin-light` scoping — re-pointing tokens rather than editing ~50 components — is the correct architecture, and it's why today's two contrast bugs were one-line fixes.

## Priority Issues

### [P0] The jobs table is effectively unusable on a phone
`JobsTable.tsx:129` sets `min-w-[900px]` inside an `overflow-x: auto` wrapper, with no card fallback (`grep` for `sm:hidden` in `components/admin/` returns only the header's dept name). On a 375px phone that is 2.4 screens of horizontal scrolling, and the **Status** column — the highest-frequency action in the product — sits ~700px to the right.

**Why it matters**: PRODUCT.md names this exact user ("department operators update production stages from the factory floor on phones and tablets") and principle 4 says stage updates must be "reachable with a thumb." The current layout contradicts the product's first principle.

**Fix**: Below `sm`, render each job as a card — PO + party as the title, status chip and delivery countdown as the body, stage control as a full-width bottom action. Keep the table from `sm` up.
**Suggested command**: `/impeccable adapt`

### [P1] No error boundaries anywhere in the App Router
`find app -name "error.tsx" -o -name "global-error.tsx" -o -name "not-found.tsx"` → **0 results**.

**Why it matters**: any throw in a server component — Supabase unreachable, a bad env var, the `/track/[po]` lookup failing — drops the user on Next.js's default error page. For a client on the public portal that's a brand-breaking white screen; for floor staff it's a dead end with no path back. PRODUCT.md principle 5 says unhappy paths are "where trust is won."

**Fix**: `app/error.tsx`, `app/admin/error.tsx`, `app/track/error.tsx`, `app/not-found.tsx`, plus `loading.tsx` for streaming. Each on-brand, each with a recovery action (`reset()`, back to dashboard, re-search PO).
**Suggested command**: `/impeccable harden`

### [P1] Keyboard focus is invisible on ~42 of 44 admin buttons
No global `:focus-visible` rule exists in `globals.css`. Only `ExportButton.tsx` and `DeliveryDateEdit.tsx` define focus styles; `MachineBoard.tsx` alone has 19 unstyled buttons.

**Why it matters**: DESIGN.md §4 specifies a "focus bloom" as the designed focus state and PRODUCT.md commits to "full keyboard navigation, visible focus states" at WCAG AA. Users currently get whatever the browser draws, which on custom-styled dark-on-green buttons is often nearly invisible.

**Fix**: one global `:focus-visible` rule using the documented bloom token, scoped per theme, plus `outline-offset` so it clears the glass border.
**Suggested command**: `/impeccable audit`

### [P1] The dashboard opens on the project's own named anti-reference
`DashboardSummaryCard.tsx:44` renders 5 identical `glass rounded-xl` cards: label + big mono number. PRODUCT.md's anti-reference list says, verbatim: *"no rows of identical stat cards."* DESIGN.md line 216 repeats it.

**Why it matters**: beyond the self-contradiction, the row fails on its own terms — 5 items exceeds the ≤4 working-memory limit, every card has identical visual weight so nothing is primary, and no number is actionable ("On Hold: 3" — is that good? against what baseline? which jobs?).

**Fix**: Break the symmetry. Lead with the one number that drives action (jobs at risk / overdue), make it clickable to a filtered view, and demote the rest to a single dense inline strip. Add direction (▲2 vs last week), not just magnitude.
**Suggested command**: `/impeccable layout`

### [P2] No undo on the highest-frequency action
Advancing a stage writes a `job_status_logs` row and a `job_stage_timestamps` row, fires notifications, and can flip machine state — with no in-UI reversal. A mis-tap on a phone (see P0) is permanent.

**Fix**: a 5–8 second "Undo" affordance on the success toast that rolls back the stage write, or an Admin-only "revert last change" on the history panel.
**Suggested command**: `/impeccable harden`

## Persona Red Flags

**Alex (Power User)** — Coordinator working 40 jobs from a desktop.
- Zero keyboard shortcuts: no `/` to focus search, no `j`/`k` row nav, no `Esc`-to-close on most surfaces (only the overflow menu implements it).
- No saved views. The Urgent filter and status dropdown reset on every page load.
- Status changes require opening a `<select>` per row; no way to advance the 6 jobs he just checked.

**Sam (Accessibility-Dependent)** — Keyboard + screen reader.
- Cannot see where focus is on ~42 of 44 admin buttons (P1 above).
- Only 2 `aria-live` regions exist app-wide, so "Status updated to In Printing" is announced visually via toast but never to a screen reader.
- `aria-describedby` count is **0** — no form field ties to its error or hint text.
- Urgency is encoded as a row background tint plus a colored chip; for the row tint specifically, color is the only channel.

**Priya (Floor Operator, project-specific)** — Updating stages between machines, on a phone, gloves half-off.
- Horizontal scroll to reach the status control (P0) — the single worst failure in the app for its most important user.
- Several controls are below the 44px minimum PRODUCT.md mandates: the ⋯ trigger is `w-6 h-6` (24px), `JobDuplicateButton` is `px-2 py-1` text-xs.
- No offline or slow-connection affordance; a failed update surfaces "Network error. Try again." with no retry button and no queued write.

## Minor Observations

- **z-index is ad-hoc**: `z-0/10/20/40/45/50` with no named scale. The `z-[45]` added today for the machine menu is a symptom — there was no documented tier to slot into.
- **Dead fallback code**: `JobRow.tsx:309` and `JobDetailClient.tsx:288` fall back to `text-white/80` when `STATUS_COLORS[status]?.text` is missing, but the map is exhaustive over `Stage`, so this branch is unreachable — and would be invisible on the light theme if it ever fired.
- **Empty states are bare strings**, not layouts: "No jobs match your filters." offers no reset-filters button; "Queue is empty." teaches nothing about how to queue one.
- **`alt=` appears once** across all components — worth confirming the logo and any status icons are correctly labelled or explicitly decorative.
- **Focus lift on inputs** (`focus:-translate-y-0.5`) animates layout position; it's correctly suppressed under reduced motion, but transform-only would be cheaper.

## Questions to Consider

- If a floor operator only ever needed to do one thing on a phone, what would the screen look like if you designed *only* for that — and why isn't that the mobile view?
- The dashboard tells you five numbers. What decision does any of them actually change today?
- Stage advance is deliberately one-at-a-time. Is that still right when a single machine finishes 6 jobs in a shift, or is the real unit of work "the machine's output," not "the job"?
